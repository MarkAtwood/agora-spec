## The infra/comms separation as found

Never stated as a principle. SPEC's four design principles (l.44–52) are relay
blindness, federation, content addressing, MLS everywhere. "Space operator"
appears 6× undefined (l.1481, 1581, 2367, 2598, 3231, 4030). SPEC §2.5.1 and
§13.7 "trust separation" concern org vs device keys, not infra vs comms.

Supporting material:
- SPEC §11.1 (l.2924–2930) relay "subpoena testimony".
- SPEC §3.3: SpaceState signed by owner/delegated admin; Space rooted at genesis CID (l.526, 536).
- SPEC §12.2 (l.3056) `RelayServiceAgreement`: bilateral Space-owner ↔ Relay contract; enforcement by relay selection (l.1202, 3052).
- SPEC §3.4 (l.596) managed hosting: `operatorDID` = provider, `relayDID` on customer DNS; portable without re-enrollment. `operatorDID` defined l.691.
- REG l.30, 38, 126–135: relay is not the archive; firm owns logger, DID↔employee map, retention, legal hold.
- PURVIEW §1.3: bridge MUST NOT run on the relay.
- OPS l.66 writes for infra roles, explicitly not space owners; OPS l.2212 IdP stays off the relay.

## Violations of the separation (relay given comms knowledge or policy)

1. Relay must reject envelopes from banned DIDs (SPEC l.2439), enforce timeouts (l.2441), pin limits (l.1536, 1542), act on DeleteEvents (l.2962) — all inside sealed/MLS ciphertext the relay cannot read.
2. §17.8.9 Mechanisms A/B: relay must know which DIDs are "regulated" and hold DM delivery (SPEC l.3878–3911; REG l.306–308). SPEC l.3878 concedes relay knows group participants, contradicting §11.1.
3. channelToken→channelCid mapping: forbidden (SPEC l.2938) vs "normal relay operation" (l.2325); JMAP Channel exposes channelToken.
4. Presence/Typing events carry sender DID and channel path in clear (SPEC l.1797–1824).
5. OPS admin API `/admin/spaces` exposes space/channel names, types, member counts, compliance flags (OPS l.1004–1050) vs REG "relay cannot produce channel structure" (l.38, 132).
6. OPS `operate_logger` lets the relay host the compliance logger and log store (OPS l.502–516, §10.4, §14.2) vs REG "relay is not the archive".
7. REG l.133 metadata only during connection vs OPS access-log retention 90d–1y with remote_addr (OPS l.1323, 2437).
8. Relay is MLS DS + KeyPackage directory keyed by DID (SPEC l.1108, 1125); authenticates client DIDs (OPS l.2212).
9. Prototype code: relay signs guild state and stores guild members/admins (`~/GIT/Agora-historical/relay/src/ws.rs` ~1068–1117).

## Core spec errata (SPEC)

- MLS: ephemeral events as `PublicMessage` application data (l.1463, 2549) — RFC 9420 requires PrivateMessage for application data. Device revocation "via Update commit" (l.104) should be Remove. Logger "issues a Welcome" (l.3782) — Welcomes come from the committer. KeyPackage validation checks "sender's DID" (l.1297), should be KP owner. Ban on Welcomes from IPFS-sourced KPs (l.1258, 1302) unenforceable by recipients.
- channelToken = HKDF(epochSecret) (l.1397) and TURN epochSecret[:16] (l.2732) contradict "MUST use MLS exporter" (l.3295).
- DM token derived from group ID (l.2461): static, not rotating.
- did:key immutable, yet spec relies on device add, recoverableIdentity, services, KP supply CIDs, rotation via RecoveryAssertion (l.102, 142–178, 1208). → decision issue.
- Recovery conflict resolved by self-asserted earliest `ts` (l.250): backdatable.
- DM consent applies to logger additions (l.2496) vs no consent threshold (l.3780).
- Signatures say "canonical CBOR" (l.466, 677, 927, 1534) vs §14.1 URDNA2015.
- Field drift: TextBody `content`/`mimeType` (l.1357) vs `format:"markdown"` (l.1431) vs MIME (l.1601); `senderDid`/`senderDID`, `channelCid`/`channelCID`; `/peer/v1/health` (l.799) vs `/v1/agora/peer/health`; DNS-SD `_agora._tcp` (l.876) vs `_agora-relay._udp/_tcp` (l.783); ClientHello `agora/0.1` (l.1919) in a v0.2 spec.
- TURN HMAC key published in descriptor (l.2710): anyone can mint credentials.
- Any member of a logging-enabled Space counts as "regulated" → all their DMs logged (l.3762). Overbroad.
- No default MLS ciphersuite outside MIMI (0x0001 at l.3439).
- Stubs: Mainline infohash TBA (l.1012); pinned context hash missing (l.3392); `test-vectors/` required (l.3386) but absent; `JmapTokenRequest` (l.2170), `QuotaGrant`, `ChannelStateMutation`, full `RelayAd` undefined; extension registry nonexistent (l.4135); Lamport timestamp not in schema (l.1082); `roles: [...]` elided (l.572); Appendix B item 3 is not a question.
- Dropped from v0.1 drafts: MobileCoin/Monero/on-chain BTC rails; IPNS directories; Corundum credit for peering model; SMTP gateway (became vague "AETP").

## Identity / enterprise errata

- Org controls every employee did:web doc (O365 §3.2 controller) → can insert device keys; "org cannot impersonate" (O365 §1) holds by policy only. Unstated.
- No employer→personal portability; leaver DID tombstoned permanently.
- ENROLL produces did:key; O365/GSUITE assume device keys registered into did:web. Unreconciled.
- ENROLL is a Discord migration tool (`discord2agora`, `discordUserId`); the general `agora-enroll` adapters (teams/okta/oidc/saml/slack) referenced by UNIV §8 and O365/GSUITE do not exist.
- ENROLL §5.2 generates recovery key in browser WebCrypto vs SPEC §2.4.1 MUST NOT be in networked device/software keystore.
- O365: credential precondition (§1) vs optional (§4.3); credential issued after device key (§4.2) vs vcPresentation required to register device key (§5.6 cond. 4) — circular for first device.
- O365 §6.4: org revocation key signs RecoveryAssertion vs SPEC §2.4.1 user recovery key only.
- UNIV: DID path from externalId (§4.2) vs UPN/encoded-id (§1, §6.2); admin paths `/v1/admin/*` vs `/v1/tombstone`; Workday `LEAVE_OF_ABSENCE` vs `LEAVE`. Termination semantics not normalized across sources.
- PURVIEW §1.2 "propagates deletion via Graph delete" vs §6.2–6.3 MUST NOT delete (present in ATTIC too).
- PURVIEW mailbox/To: three-way conflict (§3.1 senderUPN, §3.2 compliance officer, §4.1 each regulated member). `From:` format conflict (§3.2). `ts` header undefined (open issue 1). §5.2 VTC gaps use DM audit field. §2.3 puts M365 UPN in public DID doc (privacy leak). §3.1 draft-then-send would deliver mail; `/messages/import` and x-header searchability unverified against current Microsoft docs.
- LEGAL: logger "silent member" vs mandatory disclosure; logger non-removal enforced only by regulated user's own client. HIPAA BAA with relay operator despite "relay holds nothing".
- Vendor detail (Graph, Okta, Workday payloads) belongs in non-normative profiles.
