# Suggested changes to draft-atwood-jmap-* (good regardless of Agora)

Status: suggestions only, 2026-10-16. Decision D5 (agora-pozi.28.5) says Agora carries the drafts under its own profile. Nothing here has been applied to `~/PROJECT/jmap-chat-spec/`. Every row was checked against the -00 draft text. Citations use kramdown anchors or heading names, because the drafts have no section numbers.

## Summary

There are three main suggestions. First, fix DID lifecycle in jmap-did. Today "rotation" means the account's DID changes, and every historical object is relabeled with the new DID ({{rotation}} steps 1 and 2, {{did-property}} "Derived"). Under that rule old signed content and the identity shown on it no longer match, and it conflicts with chat-did, which uses "rotation" to mean key rotation under a stable DID. Second, add a content-free push mode to chat-push and to vtc ring push. In E2EE deployments the current "metadata-only" payload still sends sender, chat and Space names to APNs/FCM, and RFC 8291 encryption does not protect those platforms. Third, make the E2EE relay and call sections consistent with their own goals. The relay topology says relays handle "only opaque ciphertext", but Peer/* validation requires the relay to know membership, bans, permissions and plaintext mention and attachment fields. vtc also lets the server know call membership and the active speaker even when `e2eeEnabled` is true.

## Agora-only overrides (do not change the drafts for these)

The Agora profile handles these. They are deployment choices, not draft defects.

- Ciphertext CIDs only, CIDv1 multihash. Plaintext `sha256` never reaches an IO. The draft's plaintext hash stays valid for non-E2EE servers.
- Content-free push through the IO push proxy is mandatory, not optional.
- No relay implements Peer/*. IOs carry envelopes only. Peer/* is used only between CO components or inside MLS.
- did:webvh is the default method, and a did:web key is never trusted outside the verified webvh log.
- No server-held user keys at all, including the employer case outside a CO.
- DIDs stay stable. `senderDid` comes from the MLS credential at receipt and is stored, never re-derived.
- Slow mode, invite `maxUses`, ban and broadcast-mention gates are enforced by clients or CO components against CO-signed Space state, never by a relay.
- vtc is a vocabulary source only. spec/06 governs media, signaling, SFU and recording, and VTCCall/VTCParticipant are not server-owned objects.
- JMAP objects travel as plain JSON inside an Agora JSON-LD wrapper (`@json` literal). No per-draft JSON-LD contexts.
- Agora renames its own relay `Message` type to avoid the name clash with chat `Message`. That is an Agora change, not a draft change.
